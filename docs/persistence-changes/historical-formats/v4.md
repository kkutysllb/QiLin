# Session V4 persistence format

English | [中文](v4.zh.md)

## Summary

Inspect the V4 persistence types captured before the V5 writer change. V4 records first-class tool-role results, producer-owned message sources, developer-role events with name-only tool additions bound to historical request headers, a forked turn/end reason variant, generation-scoped delivery watermarks, and plugin-namespace ignorable records. This snapshot preserves the complete declared inventory at that V4 checkpoint.

<a id="characteristics"></a>
## Format characteristics

These facts describe the selected checkpoint. The generated tables below preserve the exact field types and optionality.

Ordinary tool results are flat tool-role messages with ordinary content blocks, and message sources are producer-owned records instead of released plugin wrappers. Developer-role events require an open step, store a toolName per addition, and reference an earlier request/header for tool schemas. The forked variant of turn/end.reason carries child-owned error results, and delivery ownership is validated against generation-scoped watermarks. Plugin records are ignorable events in the `plugin:` namespace retained on a best-effort basis.
