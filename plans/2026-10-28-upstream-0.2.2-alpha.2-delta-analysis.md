# 上游 0.2.1-rc.3 → 0.2.2-alpha.2 差异分析

- 日期：2026-10-28 · 取材源：本地 fork `/Users/libing/kk_Projects/deepseek-harness`，目标 tag `dsh-v0.2.2-alpha.2`（2026-10-28 02:17）与 `dsh-v0.2.1-rc.4`（2026-10-26），基线 tag `dsh-v0.2.1-rc.3`（2026-10-23 11:29）。**不得从 kcoder/* 取材。**
- 规模：区间 2170 个提交（first-parent 243 个，其余为 PR 合并内的提交）；全仓 7251 文件、+311322/−695812 行。其中 `rc.3..rc.4` 只有 4 个 first-parent 提交、368 文件、+593/−376；`rc.4..alpha.2` 是 master 积压的 243 个 first-parent 提交。**两个 tag 不是相邻 master 点**（rc.3 树是发布分支快照），所以只能按树对树 diff 判归属，不能按日期。
- 新增包 26 个（§7.1）；删除包 0；`SESSION_FORMAT_VERSION` 上游两端都是 4，**未变**；QiLin 侧 writer 常量已是 5（`packages/core/session/src/types.ts`），自上而下领先一个世代，见 §4.2。
- QiLin 基线：`main` 头部 3.1.7（352 个包）；上游对齐停在 rc.3（`plans/2026-10-24-upstream-0.2.1-rc.2-to-rc.3-*` 两文档）。

> **范围事实**：上一轮对齐明确把 master 漂移排除在批次之外（rc.3 之后 1533 个提交不入批）。本轮 `dsh-v0.2.2-alpha.2` 正落在 master 主干上，`rc.4..alpha.2` 的积压工作**就是**那部分漂移的正式化。它不是可一次吞下的批次：Liveshare 协作面（单提交 +59734 行）、Forge 工作树与变更请求（4 个新 Host 包 + 87 文件 UI）、实验性统计视图（+13260 行）、推荐与 action cards 簇（218 文件）、工具执行器插件化（PR 489 文件）等，各自是独立的多轮工程。

### 4.2 持久化

QiLin writer 常量是 5、上游是 4；QiLin 的 v4→v5 邻接迁移（`packages/session/session-format-v4-to-v5`）已存在，finalized baseline 只到 v4。上游本区间只新增一条在范围内的确认记录 `skill-catalog-incomplete`（skill 目录读取不完整时的事件标记）。**它必须用 `pnpm run persistence-changes --record` 在 QiLin 树上重新生成**（上游 `previous` 钉在越界的 `action-card-status` 上，QiLin 的链不同），随后 `--prose` 双语与 `doc-sync`。

`tool/result.value`（规范工具结果持久化）**净效果未落地**：上游先加（`102b42d14a`）后撤（`5626ae2391`，检视能力整体搬进 `client-ui-trajectory`），`dsh-v0.2.2-alpha.2` 树上不存在该字段 —— **不得移植**。

### 4.3 运行时与 vendor

- Node 门槛 24.9（取消 22）；`packageManager` pnpm 11.28.5。
- vendor 与新包**完全解耦**：27 个新包对 `rawConfig/effectiveConfig/resolveConfig` 的引用为空，新包 peer 一律 `workspace:~`。
- QiLin 侧真冲突只有一处：`vendor/cordis/src/fiber.ts` 的 `update()` 返回类型被本仓收紧为 `Promise<void> | undefined`，与上游重写的函数体同一 hunk。
- loader 新 resolver 会在配置所在 package scope 写 `<scope>/.cordis/{.gitignore,resolve.mjs}`，且**失败也缓存**；对仓库卫生与 profile 目录的影响需实测（对齐计划 §4 风险 R2）。

## 8. 优先级建议、品牌红线与待拍板项

### 8.1 建议的批次顺序（跨多次会话）

1. **B0 rc.4 闭环**（mcp-client 能力门控 + 会话视图提示）：最小、可独立验收，先闭合一个正式 tag。
2. **B1 模型目录自动刷新与徽章**（`llm`/`llm-deepseek`/`llm-deepseek-api-key`/`ui-model-selection`/`llm-replay`）：延续 3.1.7 的 listing 线，闭环 rc.4 指南所述契约（`settings`/`changed`/异步 `dispose`）。
3. **B2 Markdown 渲染修复**（`ui-primitives`）：零依赖、用户可见、测试齐备。
4. **B3 客户端抛光子集**（输入框统计 tooltip 等）：独立可测。
5. 之后按 §6.1/§4.1 的依赖序推进工具执行器插件化（最大破坏面，需独立成批并与迁移指南同批）、projection 句柄化、Agent model selection、控制器三分、vendor 升版。

### 8.2 红线

1. **品牌与本地化**：文案走 typed dictionary 与 `t`；`verify-client-ui-i18n` 必须绿；不把上游产品名与账号栈内容带进来。
2. **账号栈**：不引入 `llm-deepseek-account` 与 deepseek-account 栈。
3. **web_fetch 地址限制**：QiLin 的 `policy.ts`/`network.ts` 地址策略属安全面，上游的"取消限制"默认**不跟**。
4. **会话格式**：只允许相邻迁移且不移动/覆盖已提交世代；本批不改 `SESSION_FORMAT_VERSION`。
5. **本地特性不回退**：settings 自绘标题栏/麒麟印章、chat-transcript 改造、QiLin 桌面埋点、headless 的 PTC 默认。
6. **取材边界**：只读上述两个上游 tag 的树；`kcoder/*` 不取材。
