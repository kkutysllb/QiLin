## 2. 施工机制与工具链

### 2.1 两条既有路径

| 路径 | 做法 | 用过的轮次 | 评价 |
|---|---|---|---|
| A 树改名三方合并 | `pathmap.json`（路径改名映射）+ `final-transform.mjs`（作用域/字面量改名）→ 合成两个提交 → `git merge-tree --write-tree` | 0.1.5-rc.2 → 0.1.6-alpha.1 | 一次性可搬大块，但改名非逐字节精确（残余差异约 2722 文件 / 8216 行），冲突量 558 个，需逐个人工判语义 |
| **B 逐批语义移植** | 按主题分批，人工把上游改动落到 QiLin 同构文件上，每批自成一次提交并各自验绿 | **0.1.7-alpha.1 → rc.1 → rc.2（最近两轮）** | 冲突面小、可回滚、可并行分派；代价是人力 |

**本轮采用 B。** 依据：本轮 delta（261 提交）比 0.1.6 那轮（550 提交 / 3942 文件）小一个量级，且**结构高度稳定**（`SessionEventMap`、`SESSION_FORMAT_VERSION`、`vendor/`、`typert/` 全区间零变化），人工移植的收益/成本比明显更好。路径 A 的工具仍在 `.upgrade-0.1.6/work/`（`final-transform.mjs`、`pathmap.json`、`derive-map.mjs`、`rehearse-*.mjs`），**仅当某一批出现「整目录搬迁」级工作量时局部借用**（本轮无此情况）。

### 2.2 每批的标准工序（八步，缺一不可）

1. **预检「是否已在树中」**：对每个上游落点先 `test -e`/`grep` QiLin 现状，区分「已有且同构」「已有但已偏离」「不存在（净新增）」三类，写进该批工作记录。
2. **取上游原始形态**：`git -C /Users/libing/kk_Projects/deepseek-harness show <sha>` / `show dsh-v0.2.0-rc.1:<path>` 直读，**不看 commit message 转述**（本区间有 revert 陷阱）。
3. **品牌与字面量归一化**：按附录 A 映射改作用域名/路径字面量/环境变量/CLI 名。
4. **保护 QiLin 自有面**：附录 A 的「QiLin 独有包清单」内文件**只能按符号增量修改，禁止整文件覆盖**；含 `ACCOUNT_*`/桌面分支的上游文件需逐处判定删除而非照抄。
5. **测试与金样同批**：单元 spec、e2e、`snapshots/**` 期望、`apps/web/tests/expected/**` 必须与该批源码同一次提交（否则门禁红）。
6. **生成物重跑**：`gen-*` 系列按需重跑（见 §5），**禁止手改生成物**（`docs/config-catalog.md`、`docs/module-graph.*`、`docs/persistence-schema.json`、`packages/extensions/*/src/**/catalog.ts`、`slot-catalog.ts`）。
7. **门禁验绿**：跑该批的必跑集（§5），记录实际命令与结果。
8. **提交与留档**：一次提交一个批次（可分多个提交但同一批内保持逻辑完整），提交信息写清上游 sha 与 QiLin 决策；决策类变更补 Agent Note 三件套。

- **默认在 `main` 上按批提交**（沿用 rc.1/rc.2 两轮既有做法：批次各自成提交直落 `main`）。

## 4. 批次计划

优先级：高＝阻断或正确性/可用性；中＝能力与体验；低＝可推迟。

### B0 类型与门禁工程准备（高 / 无依赖 / 0.5 天）

- **目标**：先把「同批否则全红」的构建面铺好，后续批次才能验绿。
- **上游落点**：`上游提交「fix(build): fold desktop keyboard tests into client typecheck」`（删 `tsconfig.desktop-keyboard-tests.json` 折入 client）、`tsconfig.base.json`（+4 paths：`client-product-analytics` ×3、`dsh-otel`；+2：`ui-settings-session-log`、`experimental-schedule-bundle`）、`tsconfig.host.json`（+3 references、+3 e2e include）、根 `package.json`（`gen/verify-scoped-events` 改 `node --max-old-space-size=4096 --import tsx/esm`）、`scripts/no-unknown-casts.baseline.json`（−3 条豁免）。
- **QiLin 落点**：`tsconfig.base.json`、`tsconfig.host.json`、`tsconfig.client.json`（**只吸收"删除叶配置 + references 重排"的形式，不吸收 6 条 `apps/desktop/**` include** —— QiLin 该叶配置早已删除）、根 `package.json`。
- **步骤**：① 预检四个上游 tsconfig 与根 package.json 的当前 QiLin 形态；② 只新增本轮到 B3/B5 真正需要的 paths/references（**不要预埋未落地的包名**，否则 `verify-tsconfig-paths` 会指向不存在的目录）；③ 改 `gen-scoped-events`/`verify-scoped-events` 的内存参数；④ 删 3 条 `no-unknown-casts` 豁免（逐条确认对应文件已被清理，否则门禁会红）。
- **验收**：`pnpm run verify-tsconfig-paths`、`pnpm run constraints`、`pnpm run verify-no-unknown-casts`、`pnpm run typecheck`、`pnpm run test:docs`。
- **DoD**：四条门禁全绿；`tsconfig.base.json` 未出现任何指向不存在目录的 path。
- **回滚**：单文件级 revert。
- **风险**：低。唯一坑是「预埋 paths」——上游是**同一批**加包与加 path，本计划拆批时必须**随包加 path**。
