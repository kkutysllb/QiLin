## 1. 已确认决策

### D1（2026-10-15）用户文本的凭据脱敏：走 fork 投影加最小装饰源，不整放上游 UserText 注册表架构

- **问题**（delta 分析 1.1-2 遗留）：上游是「规则注册表 + 业务节点 slot」（`uiConversation.userText.register(rule)` + `conversation.user.text.node`），QiLin 是 `ui-primitives` 内写死的投影函数 `projectUserText`。移植需先定架构路线。
- **决策**：采纳 **fork 投影加最小装饰源**。凭据识别与掩码实现为 `ui-primitives` 内部模块，作为 `projectUserText` 的第五类装饰源（secret），优先于全部引用装饰；眼睛控件只在交互文本（已发送消息气泡）渲染，队列行与 goal 命令回显保持默认遮住。
- **理由**：
  1. QiLin 现有四类装饰源全部由调用方数据派生（`sessionLabels`/`slashNames`），不是插件注册出来的；上游注册表的存在理由是让 `ui-goal`/`ui-reference`/`ui-skill` 各插件认领区间，而 QiLin 已用自己的 props 通道表达了同一效果。
  2. `packages/AGENTS.md` 要求「Require a current owner and need」：QiLin 当前没有需要 `userText` 注册表的第三方消费者，整放等于建一个无当前消费者的抽象。
  3. `ui-primitives` 是 `packages/client/AGENTS.md` 指定的共享静态宿主（baseline 模块），投影与扫描器必须同侧；把扫描器放进新 feature 包会形成 ui-primitives → feature 包的反向依赖。
  4. 对账成本：整放约 21 KiB 侵入式改造 + 重述既有四类装饰源；最小装饰源约 300 行、行为等价。上游自带的 `regex-oracle` 等价测试也表明「正则参考实现」是该行为的合法等价物。
- **影响面复核**：本窗口其余 28 条发布说明条目无一条依赖 `userText` 注册表（goal/ref/skill 三条内置规则是既有能力的实现细节，不是独立条目），故该决策不阻塞其它条目。
- **被舍弃的方案**：整放上游 `contract/user-text.ts` + `user-text-registry.ts` + `user-text-document.ts` + `UserText.tsx` + keyed slot，并把四类装饰源改写为规则。
- **上游对照点**：`packages/client/ui-secret-mask`（24 文件）、`ui-conversation/src/client/contract/user-text.ts`。

1. **只改显示**：消息正文、复制内容、模型输入保持原字符；本批不得把掩码写回任何日志、事件或请求。
2. **vendored Cordis 冻结**：本批不得触碰 `vendor/`。
3. **已发布 Session 格式冻结**：本批不新增、不改动 `SessionEventMap` 成员。
4. **ui-primitives 不得引入新的 workspace 值依赖**：扫描器留在包内，`package.json` 的依赖清单不因本批扩张。
5. **产品可见文案归 locale**：眼睛控件的可访问名由调用方（ui-chat）从自己的 locale 字典传入，`ui-primitives` 不落地任何文案。

**由此确定的配方（下次直接照写）**
1. **模式**：回环 + `--port 0` 下 `/status` 报 `mode: "single-origin"`——运行时由部署**同源**转发（`tenants.ts:840-856` 的 forwarding 分支 + `routingCookie`），所以 Node 侧探针继续用**部署 origin**，旧助手的 `{origin, cookie}` 形状可原样保留。
2. **建账号**：`qilin tenants add <username> --password-stdin`，密码从 stdin 管道传入（`apps/cli/src/tenants-roster.ts:65,192`）。探针里没传密码即失败，故必须走这条。

4. **浏览器也要带上该 cookie**：登录后 `page`/`browser context` 需注入同一 cookie（Playwright `context.addCookies`），否则 `page.goto(部署根)` 仍停在登录页——这正是本文件 12 个用例当前卡住的同一处。
5. `disableAccountGate()`（写 `accounts: enabled:false`）**不足以**关闭门禁：实测仍 302 到 `/?next=/workspace`。所以要保留门禁并**真正登录**，而不是试图关掉它。

**待办（可一次改完）**：在 `apps/web/tests/smoke-real.e2e.ts` 里把 `authenticatedWeb()` 改成"建账号 → `/api/auth/login` → 返回部署 origin 与会话 cookie"，并在每处 `page.goto` 前往浏览器 context 注入该 cookie；ready-URL 断言按上节改为部署根 + 200（`pathname === '/' `）。首个用例跑通后再铺开其余 11 个。

### B4 续 4：A（选项 1）的实机迭代记录与结论（2026-10-15 稍后）

1. **登录必须走账号作用域路径**：`POST /t/<username>/api/auth/login`。打在部署根 `/api/auth/login` 上会被部署自身应答，拿到的 cookie 该运行时从不认（表现为 `session/create failed over HTTP 401: unauthorized`）。

3. **Node 探针的 base 必须带账号前缀** `<deployment>/t/<username>`：部署在 single-origin 模式按该前缀转发到运行时并剥掉它（`tenants.ts:714-717`），所以 `${base}/api/...` 才落到运行时自己的 API。
4. `qilin tenants add <username> --password-stdin` 成功输出形如 `created smoke (<uuid>); its tenant directory is <home>/tenants/<uuid>`。

      QILIN_AGENTS_HOME: join(qilinHome, '.agents'),
      TSX_TSCONFIG_PATH: join(REPO_ROOT, 'tsconfig.json'),
