# 自主路线：不再对齐上游之后的完善方向

- 日期：2026-11-13 · 基线：会话格式 v7 与用户重试对齐落地（HEAD `27fb4fdd18`）
- 前提（用户裁决 D15）：**后续不再对齐 dsh**，以本仓自身产品目标驱动；已完成的升级作为起点而非参照系
- 用途：讨论底稿。结论（取舍与优先级）待用户拍板后，再落成独立批次计划

## 1. 现状盘点（可复核的事实）

| 维度 | 实测 |
|---|---|
| 客户端规模 | `packages/client` 77 个包；`src/client` 下 825 个 .ts/.tsx；256 个 CSS Modules（约 6,000 行） |
| 令牌 | `ui-theme/src/styles/design-platform.css` 425 条 `--qilin-*` 声明；`gradient-shadow-text.css` 200 条主题渐变；`base.css` 11 条基础变量 |
| 排版 | 字号以字面量为主：12px 222 处、13px 141、14px 112、11px 74、10px 20、12.5px 12；走令牌的仅约 70 处（`--qilin-content-font-size*` 等） |
| 间距 | `padding` 字面量 634 处、`gap` 字面量 705 处；没有间距刻度令牌 |
| 颜色 | client CSS Modules 内仍有 97 处十六进制字面量（`#000` 22、`#ADB2B8` 5…），部分为渐变/遮罩用的例外 |
| 响应式 | 宽度断点只有 6 个（767/760/560/…）；交互类媒体查询占多数（`hover: hover` 63、`prefers-reduced-motion` 54） |
| 回归手段 | `test:web` 需先 build；计划 §6.14 曾记录一次 web lane 43 失败并回退 golden |
| 既有环境红 | 快照 6 个（outside-temp `mkdtemp`、`sandbox-exec` 不可用）、expected 3 个 |

结论：**样式系统有令牌底座，但组件层基本绕过它**——排版、间距、颜色仍以字面量堆叠；布局按桌面宽度写死，跨屏适配几乎没有。这正是「UI 样式与布局」最值得先动的理由。

## 2. 六个改进域

### A. 视觉基线：令牌与排版（P0）

1. **间距刻度**：新增 `--qilin-space-1..8`（4/8/12/16/24/32/48/64），把 1,300+ 处 `padding`/`gap` 字面量逐步收敛到刻度；迁移按包分批，先聊天与侧栏。
2. **字号阶梯**：新增 `--qilin-text-xs/sm/base/md/lg/xl`（11/12/13/14/16/18），替换 12/13/14px 三档字面量（这三档占全部字号的 60%）。
3. **颜色收敛**：清理 97 处十六进制字面量里的非例外项（渐变/遮罩/主题色允许保留），把语义别名补齐（`--qilin-alias-link` 已有，缺 hover/active 成对 token）。
4. **密度模式**：`--qilin-content-font-delta-*` 已存在，扩展为 compact/standard/comfortable 三档（字号 + 行高 + 行内间距 + 控件高度），设置页暴露。

### B. 布局与响应式（P0/P1）

1. **布局令牌**：侧栏/右栏/抽屉宽度、消息列最大宽、内容留白全部令牌化（目前散落在各 CSS Module）。
2. **断点标准化**：统一定义 `--qilin-bp-narrow`（≤767）与 `--qilin-bp-compact`（≤560），把 6 个零散断点收敛；明确「窄屏时侧栏转抽屉、右栏转全屏」的行为。
3. **窗口尺寸矩阵**：桌面 1280/1440/1920、窄窗 900、平板 768 三档；当前只有聊天与少量面板考虑过窄屏。

### C. 聊天与恢复体验（P1；B5 未完项）

- 向上回看自动加载、继续生成、未聚焦粘贴路由、补丁编辑回执、上下文提示、diff 行色与语言高亮、定时任务反馈、密钥掩码、PDF 翻页——这些是**产品缺口**，与上游无关，仍值得做完。
- 新增的重试动作已有入口，但「失败后恢复」的完整闭环（重试队列、网络恢复后续跑）尚未成型。

### D. 侧栏与文件（P1；B4）

- 文件搜索、排除规则、隐藏文件、暗色浮层、特殊文件名、右栏标签体系；当前侧栏是高频使用面，收益直接。

### E. 产品能力缺口（P2；B7–B11 的自主重排）

- Office 原生工具、终端面板、MCP 动态注册、插件管理、Forge/Worktree、CUA 平台化、客户端交互细节。这些不再按上游顺序，按**用户价值**重排：若要服务「代码任务」主线，Forge/Worktree 与终端面板优先于 CUA。

### F. 工程质量（P0，前置条件）

1. **稳定的视觉回归**：确定性字体、固定视口、禁用动画的截图 lane；否则任何样式重构都无法证明「只是变好看」。当前 web lane 不稳定。
2. **环境红清零**：6 个快照 + 3 个 expected 失败要么修好，要么显式标成 host-required 并从默认门禁剥离，避免每次都要人工判断。
3. **覆盖率门成本**：`test:coverage` 按文件 100%，新增 UI 分支成本高；建议对「薄接线」给出可审计的豁免规则，而不是逐个写测试。

## 3. 优先级建议

| 优先级 | 内容 | 理由 | 规模 |
|---|---|---|---|
| P0 | 视觉回归 lane + 环境红定性 | 后续所有 UI 工作的验收前提 | M |
| P0 | 间距/字号/颜色令牌化（先聊天、侧栏、设置） | 1,300+ 字面量是样式不一致的根因 | M |
| P1 | 布局令牌 + 断点统一 + 窄屏行为 | 当前基本无响应式 | M |
| P1 | 聊天恢复闭环 + 侧栏文件交互 | 高频面，用户可感知 | L |
| P2 | 功能缺口重排（Forge/终端/Office/MCP/CUA） | 价值面广但单块大 | XL |

## 4. 建议的第一个切片（约两周）

**「视觉基线 v1」**

1. 建截图回归 lane（3 个场景：空会话、长对话、设置页；固定 1440×900 与 768×1024 两档）。
2. 落 spacing/type/color 令牌，迁移 `ui-chat`、`ui-conversation`、`ui-settings-general` 三个包。
3. 密度三档接入设置页，聊天与设置页跟随。
4. 产出前后对比截图，作为路线验收的第一份证据。

## 5. 需要拍板的问题

1. **视觉方向**：延续当前「纸感 + 极简」语言，还是借这次机会重做品牌感（更鲜明的强调色、更大的圆角/留白、自定义图标集）？
2. **目标形态**：桌面优先（1280+）即可，还是必须支持 768 平板与手机窄屏？
3. **视觉回归门**：是否引入截图门（会带来 golden 维护成本）？还是只做人工 review 的前后对比？
4. **功能优先级**：下一阶段是继续「编码任务主线」（Forge/Worktree/终端），还是转「通用办公」（Office/文档/CUA）？
