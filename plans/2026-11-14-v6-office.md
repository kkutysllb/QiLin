## 2. 决定

1. **只读先行**：V6 只做读取（文本、表格、幻灯片结构），不做写入/改格式；写入仍走 `ui-sidebar-documentpreview` 与外部工具。
2. **原生工具而非技能**：新增 harness 原生工具（typed schema），不依赖外部 `python`/`libreoffice` 才能读；解析器放独立 Host 包，预览与工具**共用同一份解析结果**，避免两套解读。
3. **上限与安全**：解析在 Host 侧、在 Session 工作区文件授权之内进行；包内 zip 读取设总量/单文件/条目数上限并拒绝实体扩展（zip bomb / XXE）；超大表格与幻灯片分页返回。

- **预置接入**：`presets/coding` 与 `presets/standard` 各加一行 `tool-office-read`；`packages/bundle/base/package.json` 与 `apps/cli/package.json` 补依赖，`verify-cordis-config` 227 个配置通过、`verify-package-dependencies` 85 包通过。
- **S3b 完成一半（2026-11-14）**：`office-read` 新增 `readOfficeMetadata`——只返回格式、段落数、表格数、工作表名与其单元格范围、幻灯片数、是否截断，配 4 条测试。这是「同一份解析器产出、可做缓存身份」的元数据源。
- **S3b 缓存键接入延后（决定）**：让**预览客户端**用这份元数据做缓存键，需要新增一个 Host↔Client 远程方法（Typert 契约 + 代码生成门禁），属于跨面包边界改动；在没有远程面之前，客户端无法解析 OOXML，硬做只能把解析器塞进浏览器包。故：
  - 客户端缓存键继续用它现有的文件身份（路径 + 版本 + 大小）；
  - `readOfficeMetadata` 先作为宿主侧元数据源落地并测通，等 V6 有正式远程面时再接；
  - 计划不再把「预览元数据 == 工具摘要」当作已承诺的验收项，改为记录该依赖。

## 5. 风险

- **格式漂移**：DOCX/XLSX/PPTX 细节繁多，V6 只承诺「正文、表格、幻灯片文本与结构」，其余（批注、修订、图表、嵌入对象、条件格式）明确列为不支持并进 README 限制。
- **zip 安全**：自带 zip 读取必须限条目数、解压总量与压缩比，拒绝 `..` 路径与外部实体；夹具覆盖恶意包。
- **与转换路径分叉**：预览用 LibreOffice/WASM 转 PDF，工具用解析器读结构——两者对「有多少页/多少行」可能不同，文档要写明各自口径，不要假装同源计数。
- **字体**：解析器不渲染，字体缺失只影响预览转换面，工具摘要不含字体信息。
