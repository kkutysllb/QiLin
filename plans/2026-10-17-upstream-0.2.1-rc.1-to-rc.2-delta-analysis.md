## 2. D1：DeepSeek Search/Fetch API（`feat(web): DeepSeek Search/Fetch API`）

### 2.1 新增包 `packages/web/web-deepseek-api`（18 文件 +1886）
`src/{index,search,fetch,transport}.ts` + 六份 spec（credentials/egress/fetch/redirect/search/transport）+ `web-deepseek-api.e2e.ts` + 三语 README + locale + tsconfig。
契约要点（从上游文件读出）：Search API 与 Fetch API 两个操作面，transport 统一 egress/重定向处理；凭据走 credentials 域（API key 不出现在 settings 文档），egress/redirect 有拒绝路径用例。

### 2.2 既有面改动
- `packages/web/web-search-deepseek`：provider 关闭 thinking（辅助 Messages turn 的推理无消费者），事件 `web/deepseek-search-llm-request` 的类型 SHA 变化（`cf6e3aaf…`→`0c556c9b…`），并出现新类型字面量 `"disabled"`。
- `packages/web/web` + `packages/web/tool-web`：Search/Fetch 路由接线。
- `packages/bundle/base`：组合行 + 依赖（cordis.patch.yml / package.json）。
- `packages/client/ui-settings-web-search`：**Web Search 设置页**——Search/Fetch API 开关（默认 off；需同时具备 `web` 与 `web-deepseek-api` 名称空间才显示）、API key、两个 base URL、Messages 的 max searches / Search API 的 results per search（1–50，默认 10）、覆盖态徽标与重置。
- `apps/web/tests`：plugin-config 期望、web-search-round e2e、scaffold 支持。

## 4. 六维审计预判

- **兼容/接线**：D1 的开关需要 `web` + `web-deepseek-api` 两个名称空间同时在场才渲染；`bundle/base` 行缺失会让设置页静默隐藏开关。D2 是客户端插件行，缺失无副作用但角标不出现。
- **持久化**：`web/deepseek-search-llm-request` 类型 SHA 变化属 same-version 字段扩展；需按 `docs/cookbook/reviewing-persistence-type-changes.md` 补记录并过 catalog 门。
- **安全**：D1 新增对外 egress（search/fetch），上游带 egress/redirect/credentials 拒绝路径用例；API key 经 credentials 域写入，不进 settings 文档、不回传字面量。
- **性能**：thinking 关闭是 D1 内含的延迟/成本修正。
- **死代码/重复**：两个新包自包含；D1 的 transport 是共享实现，不引入跨包克隆。
- **类型**：无 `any` 新增面；客户端插件走既有模型标签槽。
