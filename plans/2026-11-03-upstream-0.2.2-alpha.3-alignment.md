### 会话语料 replay 漂移（已完成）

headless 语料在 rc.5 之后一直有 56/127 红，根因是 **后台子会话的结算通知在回合内被排空**：父会话被通知唤醒多跑一轮模型调用（第 7 次），而录制脚本只供 6 段片，llm-replay 报 `script exhausted`；Cordis rc.11 的调度语义变化使该唤醒稳定出现。修复方式与结论：

- 逐场景 `QILIN_SNAPSHOT=refresh`（127 个场景各跑一次）消除了「首个失败场景阻断共享 sidecar 重写」的级联：56 → 3。
- 4 个脚本化场景（advanced-toolchain、advanced-toolchain-runtime、subagent-acp-diagnostic、subagent-depth-two-rejection）补 `replay.override.json` 的结算轮供片（前者新建 override 并在 manifest 声明 `replay.override`，后两者在既有数组末尾追加一段文本项），refresh 与 replay 均绿。
- `fs-policy-reject` 是 B4「观察策略默认关」后的场景级依赖：headless harness 现在支持场景级 `runtime.cordis.yml` 补丁（对齐上游），场景用它显式开启 `fs-observation-policy`，拒绝写入的断言恢复成立。
- `background-confinement-failure`、`background-job-admission` 的夹具里 job id 半程记号化（job 记录已是 `{{id:1}}`，正文仍是字面量），按「夹具是归一化不动点」把它们统一改成 `{{id:1}}`。
- 结果：headless 语料 **125 通过 / 2 跳过 / 0 失败**；SDK 语料仍 **28/28**。

九行组合因此仍不能直接开：这些 SDK 场景的 header class 与 headless 共用（`default/default`、`image/image` 等），pin sidecar 来自 headless 名册；一旦 SDK profile 多出 `ask_user_question`/`present`/`schedule_*` 等工具，头比较必然失配。要落地需把 SDK 语料改成 SDK 自有 composition/class（含独立的 cordis 补丁属主与 pin），属于独立一批。
