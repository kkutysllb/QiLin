# QiLin 3.0.0：收敛到 DSH TypeScript 核心的设计

状态：已批准（2026-09-12）
分支：3.0.0
基线：本地 fork dsh-v0.1.5-rc.2

## 1. 背景与目标

QiLin 当前是 Python 引擎（qilin + app，约 14 万行 / 587 文件，测试 1.37 万行）加 Next.js 前端（web-demo，约 4.95 万行 / 334 文件）的双栈产品。
DSH 0.1.5-rc.2 是 Cordis 插件化体系（2793 个 TS 文件、962 个 spec），能力以 ctx.* 服务暴露，发行形态由 profile 与 bundle 组合，且原生使用物理路径。

本次重构的目标：

1. 把 QiLin 收敛到 DSH TypeScript 核心，成为 dsh 的产品发行版；
2. 侧边栏、输入框、消息渲染、交付物四区按 dsh 的 client 插件架构重建；
3. 彻底删除 /mnt/user-data 虚拟路径机制，保证物理路径；
4. 完全删除 Python 引擎与渠道，渠道以 TS Cordis 插件重写；
5. 成功后把 3.0.0 提升为主分支。

## 2. 决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 基线 | 正式标签 dsh-v0.1.5-rc.2，不用 kcoder 分支 | 避免把临时集成差异带入 |
| 仓库形态 | dsh 源码整体并入 QiLin 仓库作为核心 | 可自由改造核心，满足完全参考 |
| 前端四区 | 沿用 dsh client 插件架构，按 dsh 实现重建 QiLin 品牌 UI | 同时满足完全参考与样式全部删除重构 |
| Python | 全部删除，渠道 TS 重写 | 单栈统一 |
| 主分支切换 | S5 全部验收通过后切换 | 期间 main 保持 2.x 可回退 |

## 3. 目标架构

3.0.0 分支的树以 dsh-v0.1.5-rc.2 的完整源码为主体：apps/、packages/、python/、docs/、scripts/ 等。
QiLin 产品层新增为 dsh 约定的独立包组 packages/qilin/：

| 包 | 职责 |
|---|---|
| brand/ | 品牌标记、名称、主题色令牌 |
| profile/ | qilin profile，package.json 的 qilin.profile 声明 bundles |
| bundle/ | cordis.patch.yml，在 dsh-base 之上叠加 QiLin 插件 |
| client-ui-*/ | 四区 UI 的 QiLin 品牌实现 |
| channels/ | 8 个渠道的 TS Cordis 插件 |
| community/ | 搜索与数据 provider 插件 |

上游包继续使用 @deepseek-ai/* scope 不修改，QiLin 包使用自有 scope，以最小化上游同步冲突面。
启动方式：dsh --profile qilin web。

## 4. 前端四区设计

删除整个 web-demo。四区采用 dsh 的实现与数据流：

| 领域 | 采用的 dsh 实现 | QiLin 侧工作 |
|---|---|---|
| 侧边栏 | ui-sidebar 的 sidebar.* 槽位与 ui-layout 的列宽折叠 store | 品牌行、配色、工作区树呈现 |
| 输入框 | ui-conversation 的 Lexical ComposerContentEditable、input/machine、session 队列 | 品牌化样式、占位与命令菜单 |
| 消息渲染 | ui-chat 的 session wire event 到 typed ChatNode 投影与 ChatNodeSeat | 品牌化排版与视觉细节 |
| 交付物 | ui-deliverables 的 produced files 与 present 显式声明 | 品牌化卡片与打开行为 |

要点：QiLin 现用启发式 groupMessages 与 parseAssistantSegments 渲染 LangGraph 消息数组；改为 dsh 的先投影成稳定 typed node 再渲染，以取得更强的滚动与历史分页契约。

## 5. 物理路径设计

删除清单（QiLin 专有，dsh 无对应物）：

- qilin/config/paths.py 的 VIRTUAL_PATH_PREFIX 与 resolve_virtual_path；
- qilin/sandbox/tools.py 的虚拟与实际映射、主机路径回写与掩码、命令改写；
- app/gateway/path_utils.py 的统一 virtual resolver；
- app/gateway/routers/artifacts.py、uploads.py、skills.py 的 virtual_path 与 artifact_url 出口；
- app/channels/manager.py 的 /mnt/user-data/outputs 前缀白名单；
- web-demo 侧的 virtual_path 显示与重写；
- 各 provider（local、boxlite、tenki、e2b、aio_sandbox）的 /mnt/user-data 挂载协议。

替换为 dsh 的物理模型：

1. 模型可见路径为 session cwd 相对路径或明确绝对路径，由 tool-fs 按 session header 的 cwd 解析；
2. 写入越权由 fs-sandbox 按 read-only、workspace-write、danger-full-access 做规范化后重校验；
3. 跨 UI/API 文件寻址使用 typed FsTarget 与 dsh-resource://file 地址；
4. 上传使用内容寻址附件（DSH_HOME/attachments/v1，SHA-256）；
5. 交付物使用显式 present 声明。

安全约束（必须遵守）：

- 不得把虚拟路径简单替换为裸绝对路径，那会暴露主机路径并放大任意文件读写面；
- /api/file 的认证即绝对路径读取必须收敛到 session 与授权根围栏，拒绝 .. 与 symlink 逃逸；
- 禁止把主机绝对路径回显给模型或外部渠道。

## 6. Python 与渠道处置

删除：qilin/、app/、tests/、config.yaml、pyproject.toml、web-demo/。
保留：python/（dsh 自带 SDK，属上游核心）。

8 个渠道（飞书、钉钉、企微、微信、Slack、Telegram、Discord、GitHub，约 1.06 万行）以 TS Cordis 插件重写，需承接原有去重、连接身份、运行策略逻辑。
这是风险最集中的一段，各平台 SDK 在 TS 侧成熟度不一。

## 7. 迁移阶段与验收标准

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| S0 骨架 | dsh 源码入 3.0.0；建立 qilin profile、bundle、brand | dsh --profile qilin web 可启动并可用 |
| S1 物理路径 | 确认无虚拟路径层；清理遗留常量与文档 | 全仓不再出现 /mnt/user-data 与 virtual_path 语义 |
| S2 前端四区 | 删除 web-demo；接 dsh ui-*；落 QiLin 品牌与配色 | 四区功能可用，品牌与配色生效 |
| S3 渠道重写 | 8 个渠道的 Cordis 插件 | 每渠道收发消息可用 |
| S4 产品能力迁移 | config.yaml 语义转 settings/patch；社区 provider；鉴权、token 预算、调度、skills、memory | 对应能力有测试覆盖 |
| S5 收尾 | 清理遗留常量与文档；跑 dsh 契约与 e2e | 全量测试通过；3.0.0 升为主分支 |

每阶段执行纪律：先跑现有测试，再改，再跑测试与类型检查，报告证据后才进入下一阶段。

关于删除时点的修正：S0 把 dsh 源码整体入树时，路径冲突（README.md、docs/、scripts/、tests/、package.json、pyproject.toml、.gitignore）使新旧两套树无法共存于同一分支，
因此旧 Python 引擎与 Next 前端的移除实际发生在 S0，而不是 S5。旧代码在 main 与 2.0.0 分支完整保留，可随时回退与对照。S5 只负责最终清理与验收。

## 8. 风险与未决

1. 上游同步成本：dsh 源码入树后，跟进上游需要人工合并；rc 阶段 API 不稳定。
2. 渠道重写：TS 侧平台 SDK 成熟度、去重与连接身份语义需要逐渠道验证。
3. 协议适配：LangGraph 的 thread/run/message 与 dsh 的 session/wire-event/projection 在 ID、顺序、断线、取消、错误上不等价。
4. 交付物语义：QiLin 的 artifacts 是路径清单，无法证明 mutation 成功；dsh 的 present 是显式声明。
5. 安全边界：/api/file 与附件通道需要单独审计。
6. 未决：是否需要为旧的持久化数据提供只读兼容；config.yaml 中哪些配置需要保留为产品默认。
