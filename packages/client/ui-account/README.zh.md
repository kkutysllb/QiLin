# @qilin/client-ui-account

[English](README.md) | 中文

## 概述

账户菜单是页脚的账号行：头像中携带已登录地址的首字母，收起轨道时只剩头像。一个下拉菜单承载已登录地址、设置、外观与语言子菜单以及退出登录；它是 Web 端切换主题与语言的入口、唯一的 Settings 入口，也是唯一退出登录的方式。账户事实来自账户门禁的 `GET /api/auth/status` 应答，因此在未启用账户的部署上渲染出同一个本地化标签下的行、同一个缺少身份的菜单，也没有可结束的会话。本插件不提供任何服务、不持有对话框，只贡献一个列表条目。

<a id="use-this-package"></a>
## 使用本包

`qilin` Web profile 通过 `web-app` bundle 补丁挂载本包；卸载插件会移除它在底部的条目，让侧边栏底部回到没有账户入口的状态。

| 行 | 出现条件 | 效果 |
|---|---|---|
| 已登录地址 | 门禁应答中带有账户 | 菜单标题行；地址不是链接 |
| 设置 | 已挂载设置面板 | 展开设置面板 |
| 主题样式 | 始终 | 打开浅色／深色／跟随系统子菜单 |
| 语言 | 始终 | 每个已注册语言一行，各自以自己的语言标注 |
| 退出登录 | 账户门禁已启用 | 结束会话，然后落到登录页 |

身份行与退出登录行随状态应答一同到达，因此在应答之前打开的菜单不会显示这两行；它们下方的行从首帧起就在。当前主题偏好对应的那行、以及当前语言对应的那行，是带选中标记的行。

被拒绝或无法到达的退出登录不会跳转：页面停在原处，菜单保持可用，而不是在一个从未落地的请求上关闭。

<a id="understand-the-implementation"></a>
## 理解实现

插件填充 `sidebar.footer.action` 中的一个列表条目，也就是侧边栏自己的底部洞口，并通过 `slots.inject` 等待该声明出现；侧边栏只把列状态（`wide`）交给它。文案存在本包的 `account` 字典中，经框架的 `t` 座位抵达组件。

条目声明了 `createAccountMenuStore()`：下拉菜单的展开状态，以及一次状态读取解析出的账户事实。组件通过 `props.useStore` 读取该快照、通过 `props.actions` 写入；没有其他写入方，用例也直接构造同一个 store 句柄。

`createAccountMenuInjected` 在 `apply` 中组装组件的注入面：两个浏览器读取（`readAccountStatus`、`endSession`）、服务调用（`ctx.settingsShell.open`、`ctx.theme.setTheme`、`ctx.locale.setLocale`），以及渲染器绑定为 `useTheme`、`useLocale` 与 `useSettingsPanel` 的主题、语言与设置面板来源。组件自身不接触任何服务，两个请求各自的路径与跳转目标都留在本包内。设置面板是可选的邻居：`settingsShell` 经 `ctx.get` 读取，其存在与否由一处作用域注入发布到 `useSettingsPanel` 来源上，因此没有挂载设置面板的组合仍会挂载本菜单，只是不提供设置行。

<a id="model-experience"></a>
## 模型体验

None, as the account menu renders browser chrome and registers nothing model-facing.

#### KV Cache 影响

本身没有；菜单既不向请求添加内容，也不订阅任何缓存前缀。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

这些限制描述本菜单目前做不到什么、以及什么时候需要留意。它们是当前约束，不是与其他账户界面之间的对比，也不是任务清单。

- **子菜单行自己绘制选中标记**——共享的 `Menu` 只为 `selectedIds` 中点名的顶层行绘制标记，子菜单行不带标记，因此本包自己为主题与语言当前行绘制对勾，同时仍把两个 id 交给该基础组件。等到基础组件为子菜单行也绘制标记后，应删除本地标记。
- **账户只在挂载时读取一次**——状态读取发生在底部条目挂载时，因此在另一个标签页里换了会话的浏览器，会继续显示此前的地址，直到页面重新加载。
- **被拒绝的退出登录是静默的**——菜单保持展开、页面停在原处，但没有任何提示告诉用户请求失败了；要给出错误提示，需要一个本包目前没有的文案位。
- **没有覆盖装配后底部的浏览器级断言**——随包发布的用例以直接喂入的 props 驱动组件、以真实槽位注册表驱动插件；装配面的检查目前是手工的。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者的工作上下文——点击展开</summary>

本开发备注是维护者的工作上下文：尚未决定的开放问题与方向。它明确不具备权威性——已发布行为、限制与已接受的取舍见上文各节、包代码以及链接的 Agent Note。

- 菜单是否应显示昵称或头像仍待定；状态读取背后的账户记录目前只有地址与创建时间。
- 门禁已启用但没有会话的浏览器仍会看到「退出登录」，因为登录文档读取的是同一份状态应答；要把「未登录」与「门禁开启」区分开，需要一个状态读取目前不报告的字段。
- 是否为窄列把主题与语言两行从子菜单中摊平，目前无人提出；子菜单让下拉菜单保持紧凑，而侧边栏还留着 rail 宽度。

</details>

**运行时不变式：** 不发布伴生入口。本菜单仅有的关系是它自己的 store 与注入的 slot 面，对它们不存在会各自漂移的独立观测。
