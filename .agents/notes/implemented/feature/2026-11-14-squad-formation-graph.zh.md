# Agent Note：Team 页的队伍标签与编队图

Status: implemented

[English](2026-11-14-squad-formation-graph.md) | 中文

## 问题

会话页头把 Team 与子代理数量分成两个标签，Team 页则是扁平的 roster 加共享任务板。两者都没有说明会话中的 agent 之间如何关联：运行中的 agent 属于哪条分支、谁委派给谁、每个 agent 承载了什么。协调十个子代理的用户只能读到名称与状态的列表。

## 决定

- **一个标签，一个页面。** 队伍标签位于子代理数量标签之后。它陈述 Team 规模与编队规模，并用 `ctx.sidebarRight.openTabIn(sessionId, 'agent-team')` 打开既有的 Team 标签页。它不拥有 popover，也不新建第二个页面：这个标签页就是表层。
- **步数来自宿主折叠，而不是重放。** `session-turn-outline` 新增 `turnStats` 单元，整日志按 `turn/start` 计一轮、按 `step/start` 计一步，小到可以随每个 Session 摘要下发。客户端因此无需读取各 agent 日志即可陈述其步数。计数刻意做成投影而非客户端折叠：浏览器只持有已加载的事件，编队级数字无法在本地派生。
- **Team 页以编队图开场。** `SquadFormation` 为会话家族的每个 agent 画一张卡片，所有父子连线绘制在同一张 SVG 上。卡片陈述序号头像、持久标签、活动状态、模型与创建模式、累计 token、活跃轮次耗时、已开始的步数，以及按压力着色的整数占用百分比；堆叠条把已用部分拆成计量器的系统提示词、工具与消息构成，后面留出空闲窗口，画布上方的图例为这些分段与运行中连线命名。Lead 与当前会话各带标记。连线取子节点分支的颜色，子节点运行时该连线带动画。悬停或聚焦会让该 agent、其父与子保持点亮并淡化其余；点击或按 Enter 通过持久 subagent 地址打开该 agent。
- **画布按宽度测量。** stage 通过 `ResizeObserver` 上报 client width，因此侧边栏每次调整宽度都会重排；叶节点超过一行容量时层级改为分带，而不是向两侧溢出。
- **图形旁有一条协作时间线。** `SquadTimeline` 按时间倒序列出页面持有的持久委派——父节点 catalog 的 `createdAt`、父节点标签、子节点创建模式与其步数——同一列随后是紧凑的只读任务汇总，宽面板上该列与图形并排。消息流来自 Team 投影旁注册的第二个单元 `agentMessages`：它折叠单个 Session 收到的入站 peer 消息——Team 邮箱投递与相邻 Agent 转发——带接收日志时间、持久发送方与有界预览。两种路径都落在收件人自己的日志里，因此合并绘制的 agent 即可仅凭投影得到跨 Agent 流量，不需要宿主服务扫描，也不读取第三方插件的键。
- **任务板共享悬停负责人。** `TeamBody` 持有唯一的负责人名称；悬停卡片会给该负责人持有的行着色，悬停行会点亮其负责人的卡片。
- **卡片先读摘要。** 每个摘要投影都随 Session 列表行下发，未打开过的子节点也能陈述 token、步数、耗时与模型。占用与构成属于 summary-excluded，图形因此为每个绘制出的子节点向 Host 请求它自己的 cell（每次挂载至多十六个），而不是打开该会话；合并顺序是先摘要值、后 cell 值。
- **读取保持纯粹。** `squad-model.ts` 沿 `parentId` 解析家族根，按父节点持久 `subagentCatalog` 排序子节点并追加 catalog 尚未记录的行，再从投影值派生标签、模式、活动、序号、token、耗时、占用、构成与模型。`squadBarSegments` 把占用拆成上报的构成与空闲余量，`layoutSquad` 计算整齐树，一行放不下叶节点时按层分带。图形自身不发起任何投影请求。
- **颜色来自 token 尺度。** 分支色取既有 `--qilin-*` token 的六项调色板（brand、green、amber、violet、error、blue），按顶层分支序号循环；Lead 使用 brand 强调色。客户端不引入 HSL 字面量。
- **覆盖。** `squad-model` 单元测试（家族顺序、标签优先级、活动、耗时、占用、布局、格式化）、`SquadFormation` 组件测试（chips、卡片事实、占用分段、悬停邻域、任务板驱动的点亮、指针与键盘导航、stage 测量）、`SquadChip` 测试（两种标签形态、运行标记、导航）、Team 页的悬停联动与卡片导航测试，以及 browser-plugin 测试断言第二个页头席位与 `openTabIn`。

## 考虑过的替代方案

- **单独的编队 popover 或页面。** 否决：Team 标签页已拥有 roster 与任务板，第二表层会重复页面并割裂同一投影的归属。
- **打开页面时读取每个子节点的 catalog。** 否决：为一张页面已持有的图，每个子节点各付一次 Host 读取；catalog 从未读取过的分支保持为叶节点，直到常规读取提供它。
- **dsh-context 式旋转 HSL 色相。** 否决：本客户端通过 `--qilin-*` token 着色，六项 token 调色板把颜色留在主题内，而不是新增第二个颜色来源。
- **实时自走的耗时。** 否决：活跃轮次耗时与占用按最后一次投影 cut 读取，因此同一投影状态总是渲染同一文本，页面无需计时器。
- **从已加载事件派生步数。** 否决：浏览器只看到自己分页载入的事件，未打开的 agent 会静默少算。投影才是唯一来源。
- **卡片上的计价费用。** 暂时否决：客户端没有计费价格投影，加一个属于定价特性而非编队关注点。

## 后果

- 想要悬停联动的任务板表层取用 `TeamBody` 持有的负责人名称，而不是订阅图形。
- 卡片上的新事实需要在 `squad-model.ts` 中读取，从而把每个派生值留在一个纯函数里。
- 图形是绝对定位的卡片画布，没有虚拟化；高于一行分带的编队会在 stage 内纵向滚动，窄于一张卡片的 stage 会横向滚动。
