# Agent Note: 桌面菜单栏按标准应用菜单重建

Status: implemented

[English](2026-10-28-desktop-standard-menus.md) | 中文

## 问题

桌面菜单只暴露应用生命周期：macOS 上的关于、检查更新、管理 qilin 命令、隐藏与退出，一个只含“关闭”的文件菜单，Windows 上则是标题栏里两个弹出菜单（应用与编辑）。会话与工作区入口、面板可见性、缩放、窗口命令以及任何帮助目标都缺失，应用因此更像套着网页的外壳而不是桌面产品，同一批命令只能从 Web 客户端自己的控件进入。

## 决策

- [`apps/desktop/src/application-menu.ts`](../../../../apps/desktop/src/application-menu.ts) 独占一份菜单定义：为 macOS 与 Linux 返回原生模板，为 Windows 返回 `[]`，由标题栏经 `captionMenu` 从同一份定义绘制弹出菜单。
- macOS 与 Linux 的菜单栏含应用、文件、编辑、视图、窗口和帮助。Windows 在标题栏内绘制文件、编辑、视图和帮助菜单，原生菜单只保留隐藏的开发者快捷键，因为原生菜单栏会与标题栏按钮重复。
- 文件菜单提供新建会话、搜索会话、添加工作区、macOS 之外的设置、关闭窗口，以及 macOS 之外的退出。视图菜单切换左右侧栏、页面缩放与全屏，并承载开发用的刷新、强制重新加载与开发者工具。帮助菜单打开项目主页与问题反馈，在 macOS 之外还含检查更新与关于。开发构建把重启应用与 Host 加进应用菜单或文件菜单。
- 渲染进程条目由 `installDesktopShortcuts` 的 `commandItem` 生成：显示用户当前的绑定，在 Web 客户端发布快捷键配置前保持禁用，并按命令 id 经与物理按键相同的 `shortcuts-input` 通道派发。自定义绑定因此同时改变加速键与执行的命令，既有的 revision、录制、焦点与遮罩守卫照旧生效。
- 任一已发布绑定、可用命令集合或桌面壳语言变化时重建菜单；此前的实现只为关闭加速键重建。
- 所有文案来自 `apps/desktop/src/locale.ts` 的桌面词典，英文与中文键集合保持一致，标题栏、原生菜单栏与托盘读同一批字符串。

## 考虑过的替代方案

**在 Web 客户端注册菜单并在页面内渲染。** 页面已经拥有快捷键，但产品菜单必须在页面尚未加载或崩溃时仍可用，且 macOS 要求原生菜单栏；桌面壳仍然需要这份定义。

**只写 role 交给 Electron 本地化。** role 文案跟随操作系统语言而不是应用自己的语言设置，因此在没有中文系统区域的环境里选择中文的用户会看到英文菜单条目夹在中文界面里。

**Windows 标题栏直接放应用菜单。** 标题栏已经显示产品名与窗口控制，再放一个应用弹出菜单浪费空间，而关于、更新与退出更适合放进 Windows 用户预期的文件与帮助菜单。

## 结果

菜单现在写出了桌面壳在构建期无法校验的渲染进程命令；运行中的客户端缺少某个命令 id 时，条目虽然可用却没有任何效果，这正是条目要保持禁用直到客户端发布 revision 的原因。为新的客户端命令增加菜单条目，需要该命令先在 Web 客户端注册并在 `application-menu.ts` 中命名；这里故意没有动态贡献通道，菜单因此不会与实际发布脱节。

## 验证

- `apps/desktop/tests/application-menu.spec.ts` 固定各平台模板、标题栏菜单集合、命令绑定透传与两个帮助目标。
- `apps/desktop/tests/main-startup.spec.ts` 在各平台启动真实 main 入口，断言构造出的菜单、标题栏弹出菜单与关于对话框。
- 在 `apps/desktop` 下运行 `pnpm exec vitest run` 覆盖整套用例；`tsc -p apps/desktop/tsconfig.host.json` 类型检查桌面壳。
